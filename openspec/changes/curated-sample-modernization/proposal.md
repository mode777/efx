# Proposal

## Why

`script-api-ergonomics` (ADR 0060) landed frame-space input, `mat4.transform`,
`graphics.screenRay`, `physics.debugDraw`, `math.clamp`/`lerp`, `efx.time.now`,
and `physics` teleport — and migrated the demos' *obsolete plumbing* (audio
unlock gates, pointer→frame mapping, recreate-on-teleport, local `clamp()`).
But the demos do not yet **showcase** the new conveniences: three samples still
carry a local `trs(pos, scale)` helper, `game-bot-arena` and `game-mini-golf`
still hand-roll camera-basis + cursor-ray picking, `physics-showcase` still
re-types collider sizes as render scales instead of `debugDraw`, 15 samples
still accumulate `t += dt` by hand, and `math.lerp` is unused. Separately, the
samples still hand-roll texture generation that the engine now does better or
that belongs in an asset: `game-mini-golf` rolls its own LCG noise instead of
`efx.noise`, and eight samples build a radial-falloff texture in code — the
exact byte loop the earlier exploration agreed to move offline as a shipped
image.

## What Changes

**Adopt the remaining engine conveniences in the curated samples**

- Replace the local `trs(pos, scale)` helpers (`game-bot-arena`,
  `game-mini-golf`, `physics-showcase`) and inline translate∘scale ladders
  (`game-sky-steps`) with `efx.math.mat4.transform`.
- Replace the hand-rolled camera basis + NDC cursor ray in `game-bot-arena`
  and `game-mini-golf` with `efx.graphics.screenRay(...)`; the samples keep
  only the ground-plane intersection that consumes the ray.
- Give `physics-showcase` a collider debug view toggle (a key) driven by
  `efx.physics.debugDraw()`, replacing the duplicated collider-size render
  calls it uses today to show the physics bodies.
- Replace remaining per-frame `t += dt` / `clock += dt` accumulators with
  `efx.time.now`, and manual lerps with `efx.math.lerp`, where the value is
  frame-time or a linear blend (behavior preserved; the engine clock clamps
  long stalls).

**Use `efx.noise` for Mini Golf's grass**

- Replace `game-mini-golf`'s hand-rolled LCG `noiseTexture` with
  `efx.noise.imageData` + `createTexture` (still procedural, so the sample
  keeps its "no third-party assets" contract).

**Ship a radial glow image instead of building it in code**

- Add one canonical CC0 radial-falloff PNG (`radial.png`, white with an
  alpha falloff) generated by a committed
  `gallery/scripts/gen-radial-asset.py`, copied into each of the eight
  samples that currently hand-roll the loop: `game-bot-arena`,
  `game-bloom-breakout`, `game-glow-gauntlet`, `game-mini-golf`,
  `game-sky-steps`, `particles-showcase`, `particle-plane-showcase`, and
  `blob-shadow-showcase`. Each sample loads it with `loadImage` +
  `createTexture` and tints it at draw time; the falloff loops are deleted.
- Record the new file in `gallery/samples/curated/CREDITS.md` (authored
  in-repo, CC0, regenerated by the script) for every sample that ships it.

### Modified Capabilities

- `web-gallery`: the particle-showcase and skybox/blob-shadow requirements
  drop their "prefer a procedurally generated texture" clause in favour of
  the shipped shared radial asset; the Mini Golf requirement allows the
  shipped glow image (grass stays procedural, now via `efx.noise`) and the
  Bot Arena requirement keeps procedural primitives while its glow decals
  use the shipped radial asset; a new requirement pins the shared radial
  texture asset and its provenance.

## Impact

- **Samples**: `gallery/samples/curated/{game-bot-arena, game-bloom-breakout,
  game-glow-gauntlet, game-mini-golf, game-sky-steps, particles-showcase,
  particle-plane-showcase, blob-shadow-showcase, physics-showcase}` plus the
  `t += dt` / `lerp` adoptions in the remaining showcases.
- **Assets**: one new `radial.png` per sample that needs it (same generated
  bytes), a new `gallery/scripts/gen-radial-asset.py`, and `CREDITS.md` rows.
- **Specs**: `openspec/specs/web-gallery/spec.md` deltas (above).
- **Docs**: `CREDITS.md`; no engine docs, no `docs/api`, no ADR — the change
  is sample content and a sample-asset convention pinned in the web-gallery
  spec, not an engine decision.
- **Verification**: `npm --prefix gallery run build` + the gallery smoke run
  (drives every sample headlessly), the server `verify_remote.py gallery`
  suite, then the four-target gate. No golden scenes change (samples are not
  goldens); the `package curated samples` job re-derives the sample packs
  from the new directories.

## Non-goals

- No engine/API changes; no `gradientImageData` or procedural-texture API
  (the earlier exploration settled this: demos ship offline images).
- No new samples, no gameplay changes — visual output is preserved except
  where a shared radial replaces a bespoke falloff (blob shadow).
- No change to the sample asset-pack contract itself.
