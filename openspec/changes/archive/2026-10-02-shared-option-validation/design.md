## Context

See `proposal.md` (Why) and `docs/refactoring.md` §2.1 and §5. The current
facts that shape the approach:

- **How each runtime evaluates the prelude.**
  - Desktop (`src/runtime/runtime.c` `eval_prelude`): wraps
    `src/prelude/prelude.js` as `(function(efx){ … })(efx)`, then calls the
    returned module-runtime factory.
  - Web (`src/web/js/audio.js` L213): runs
    `new Function('efx', preludeSrc)(api)`.
  - Both run the same bytes (`prelude.h`, generated by `tools/gen_prelude.py`
    and drift-checked).
- **Existing normalized forms.** The web binding already uses them for some
  domains: `__efxParticleWire` (the particle config as a float array) and the
  9-float post-entry wire. The desktop binding reads the same option bags
  directly with quickjs readers (`read_particle_config`, `read_post_entry`,
  `parse_shape`, …).
- **Liveness.** Each binding tracks it differently: desktop through wrapper
  `alive` flags, web through `__alive`. Messages already agree for liveness
  (e.g. "using a destroyed resource"); the catalog records no liveness
  divergence.
- **What already exists after `refactor-volume-core`:**
  - web `__efxRc`: one return-code → error table;
  - desktop `efx_api_opt_*` with explicit policies (coercion is one of them).
- **The catalog.** `tests/scripts/s_error_catalog.js` pins about 200 cases on
  both runtimes. Its `DIVERGENT` map lists 18 message divergences plus
  `coercion.phys-number-string`.
- **Resource exposure to scripts** is unchanged:
  - dynamic-count resources stay GC-finalized opaque classes with an explicit
    `destroy()` (ADR 0011, memory discipline ADR 0012);
  - lights stay a fixed pre-allocated bank;
  - physics wrappers stay world-held (ADR 0046).

  Only argument handling moves; no resource is created or released by the
  prelude.

## Goals / Non-Goals

**Goals:**

- One implementation of cold-path argument validation, shared by both
  runtimes, with identical error classes and messages.
- Both bindings reduced to marshalling a normalized form for migrated
  domains.
- A recorded, measured cold/hot boundary, so no hot path gets slower without a
  decision.

**Non-Goals:**

- Sharing liveness tracking or class identity between runtimes.
- Rewriting native recording or creation code. Natives keep their core calls,
  and the core keeps its own validation.
- Changing any documented default, range or option name.

## Decisions

### D1 — Natives reach the prelude as a second wrapper parameter

The prelude wrapper becomes `function (efx, natives)`.

- **Desktop:** `eval_prelude` evaluates the wrapper as a function *value*
  (no immediate call) and calls it with `JS_Call(ctx, fn, …, {efx, natives})`.
  `natives` is a plain object built by `efx_api_init`. It is never stored on
  the global object.
- **Web:** `new Function('efx', 'natives', preludeSrc)(api, natives)`.

Validators wrap the public entry, e.g.
`efx.createParticleSystem = function (opts) { return natives.createParticleSystem(__efxParticleWire(opts), …); }`.
Because the wrapper is installed by the prelude, the public function keeps its
name and its layer tag (C-implemented).

- **Why:** the private object is unreachable from scripts (ADR 0004, spec
  "Shared argument handling stays private"), and neither binding needs a new
  global.
- **Rejected — a hidden global (`__efxNatives`) deleted after install:** it
  is briefly script-reachable, and module code could capture it.
- **Rejected — validators as a separate JS file per runtime:** that brings the
  duplication back.
- **Rejected — validate in C on both runtimes through a binding-neutral
  "option reader" interface:** the web would need wasm→JS callbacks per field,
  which is slower and adds a large bridge surface for what JS does natively.

### D2 — Normalized forms: positional numbers and typed arrays; resources pass through

A validator returns:

- a flat `Float64Array` (or `Float32Array` where the native consumes floats)
  holding the numeric fields in a documented order;
- strings and enum codes as numbers;
- bulk data as typed arrays;
- resource arguments as the original wrapper objects.

Each native unpacks only that layout. Liveness is checked by the native
through its existing binding mechanism, using the same message on both sides.

- **Why:** this is the cheapest form for both the quickjs C API and the wasm
  heap copy, and the web side already uses it.
- **Rejected — plain normalized objects:** desktop C would need a property
  lookup per field, which recreates the reader code this change removes.

### D3 — Check order is fixed and documented

Each validator checks in this order:

1. arity;
2. resource arguments (type, then liveness via `natives.live(v, kind)`);
3. the option bag (known fields, then fields in declaration order);
4. cross-field constraints.

This matches today's web order.

- **Why:** the catalog pins one fault per case, but multi-fault inputs must
  still behave deterministically and identically on both runtimes.
- **Rejected — validate the bag first and leave liveness to the native:** it
  reorders errors relative to today's web behavior.

### D4 — Failures after validation are codes; one prelude table throws

Natives return `0` or a failure code. The prelude's code table (the
generalized `__efxRc`) maps each code to `[ErrorClass, message]`, with
per-call overrides.

Resource-load failures use dedicated codes:

- not found;
- unreadable;
- undecodable.

This resolves the image, glTF and audio "missing" divergences without making
both cores share a message string.

- **Why:** one message source per failure.
- **Rejected — the core returns message strings:** C would own script-facing
  text, and every core call would need a string channel.

### D5 — Canonical-message rule for the 18 divergences

For each divergent case, choose the message that:

1. names the field or API function; and
2. states the accepted form or range.

If both candidates qualify, keep the desktop text (it is the older,
documented binding).

Example resolutions recorded in ADR 0049:

- `4a.light-slot` → "light slot must be an integer 0..3" (both qualify, so
  the desktop text stays);
- `11.ps-max-range` → "max must be in 1..65536";
- `12.step-nodt` → "dt must be a finite number".

Every choice appears in the domain's catalog diff and in the ADR's table.

- **Rejected — always keep web text:** some web messages omit the function
  name ("expected an array").
- **Rejected — new wording everywhere:** it churns messages that already
  agree.

### D6 — Numbers are strict

Number-typed fields accept `typeof v === 'number'` only. Non-finite values and
ranges keep their documented classes.

- **Why:** this applies the existing `docs/js-api.md` rule ("a wrongly-typed
  field throws `TypeError`"). The web build already behaves this way, so only
  desktop physics loses `JS_ToFloat64` coercion.
- **Rejected — coerce everywhere:** it contradicts the guideline and
  widens accepted input on the web.

### D7 — The cold/hot boundary comes from measurement (ADR 0049)

R22 measures, on the Windows Release desktop build:

- **cold:** `createParticleSystem` with a full option bag ×1000, prelude path
  vs today's C path;
- **hot:** `drawQuad` with a full option bag ×10 000 in one frame.

Budget proposed for the ADR:

- a cold path may move if the added cost is < 50 ms per 1000 calls;
- a hot path may move only if the prelude path is within 1.2× of the native
  path.

The ADR records the measured numbers and the resulting list. Without
acceptance, the change stops after R22 (see Migration Plan).

**Rejected — move everything unconditionally:** quickjs is an interpreter, and
per-frame draw calls are where a regression would be felt.

### D8 — Domain order: coldest, largest and best-prepared first

1. particles (the web wire already exists);
2. post effects (the wire exists);
3. fonts;
4. physics creation and queries;
5. audio;
6. resource construction;
7. lights and cameras.

Each domain is one task group with its own catalog diff.

**Why:** early domains prove the mechanism at the lowest risk, and later
domains reuse their helpers.

## Risks / Trade-offs

- **[Risk] Desktop slows down on a migrated path.** → D7 budget, with a
  per-domain timing check before the domain's task group closes.
- **[Risk] Scripts relying on desktop numeric coercion break (BREAKING).** →
  Limited to physics option fields; the web build already rejects them.
  Documented in the `js-api` delta and ADR 0049.
- **[Risk] The `natives` object leaks into script scope.** → A spec scenario
  plus a catalog/portable test that enumerates `efx` and `globalThis` on both
  runtimes.
- **[Risk] Error order shifts for multi-fault inputs.** → D3 fixed order;
  add a few multi-fault catalog cases per domain.
- **[Risk] `prelude.h` grows and drifts.** → The V3 `gen_prelude.py --check`
  gate already exists. The growth is the moved validators (about 1 100 lines),
  offset by the larger removal in both bindings.
- **[Trade-off] Validation lives in JS for C-implemented functions.** → It is
  recorded as a deliberate layering amendment (ADR 0049, `js-api` delta, and
  the `AGENTS.md`/`docs/js-api.md` updates). Functionality stays in C.

## Migration Plan

1. **R22 (spike, go/no-go):** prototype particles on a throwaway branch,
   measure, and write ADR 0049 (status Proposed → Accepted/Rejected).
   - If **rejected**, record the measurements in the ADR (status Rejected).
     Mark the remaining task groups won't-do with a pointer to the ADR,
     update `docs/refactoring.md` §5, and abandon the change without spec
     sync. The `js-api` delta does not land.
2. **If accepted:** land the infrastructure (D1–D4), then one domain per task
   group in D8 order. Each group updates the catalog expected file and
   removes its `DIVERGENT` entries.
3. **Per domain:**
   - V1/V2;
   - V3 (`prelude.h`);
   - V4 (catalog through both runtimes, `run_web_compare.mjs`, web goldens);
   - the timing check against the D7 budget.
4. **Final:** `DIVERGENT` is empty; V5 four-target gate (Linux → Windows →
   macOS); merge to `main`; archive **with** spec sync (`js-api`).
5. **Rollback:** each domain is an independent commit series. Reverting one
   restores its per-binding readers and its catalog lines.
