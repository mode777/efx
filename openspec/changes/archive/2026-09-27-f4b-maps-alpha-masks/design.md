# Design

Implements F4b (per-channel maps + alpha masks). Motivation and scope:
`proposal.md`; behavior contract: `specs/lighting/`, `specs/3d-core/`,
`specs/js-api/`. Decisions here are numbered D1–D10 and referenced by
`tasks.md`.

## Context

`src/` is a core static lib (`platform`, `runtime`, `api`, `player`,
`render`) plus `main.c` (ADR 0003). F3/F4a shipped the mesh path: interleaved
`pos(3f) normal(3f) uv(2f) color(4f)` vertices per surface (absent attributes
default to normal `(0,0,1)`, uv `(0,0)`, color white), one GPU draw per
surface, a depth-tested mesh record holding a value-snapshotted light bank
(ADR 0019), and one uniform-driven, world-space Phong shader generated by
sokol-shdc from `shaders/mesh.glsl` (ADR 0021/0026). Materials are plain
`efx_material` snapshots (four channel colors + `shininess`) stored per
surface on `MeshData` and `Mesh` (`src/render/render.h`); textures live in a
generation-handle registry (`tex_slot`) whose native release is deferred to
frame end so recorded quads stay valid (`src/render/render.c`). The desktop
binding is quickjs (`src/api/api.c`); the web binding is the C bridge plus
`src/web/entry.js` with a 17-float material wire layout and identical
semantics (ADR 0022). F4a explicitly rejected `map`/`alphaMask` as unknown
fields and left `uvs` unread; ADR 0026 reserved the map/shader question for
this change. F2 2D behavior and its seven goldens are frozen; the F3/F4a
goldens are the current committed set.

## Goals / Non-Goals

**Goals:**

- Per-channel maps (Ambient/Diffuse/Specular/Emissive) and a material-level
  alpha mask, delivered through the existing single uniform-driven mesh
  shader with **no** per-material permutations.
- `uvs` (stored since F3) become the map/mask texture coordinate.
- Bound map textures are retained so a destroyed texture cannot dangle.
- The CPU lighting reference gains map/mask inputs so the new math and the
  cutout threshold are verified headlessly.
- Every committed F2/F3/F4a golden stays byte-identical; F4b scenes are
  additive.
- Identical semantics and errors on the desktop and web bindings.

**Non-Goals:**

- `uv` transforms/scaling/offset, texture wrap/filter controls, mipmaps,
  anisotropy, or texture arrays.
- Soft/graded alpha, alpha blending or dithering driven by maps (only the
  binary mask ships).
- Normal/light/cube maps, shadows, reflections; any consumer-visible shader
  surface (ADR 0015).
- New resource classes or new API functions — F4b extends the F4a material
  object additively.

## Decisions

- **D1 — Maps modulate a channel's RGB; alpha masks are the only alpha
  control.** For each channel, `M_c = channel.map ? texture(channel.map,
  uv).rgb : (1,1,1)` multiplies that channel's color, exactly as the spec
  equation states. The specular map modulates the specular color, **not**
  `shininess` (no specular-map alpha repurposing). Material channel alphas
  and map alphas are ignored by shading; a surviving fragment's output alpha
  stays the albedo alpha (vertex-color alpha × tint alpha). Alternative
  (diffuse-map alpha into output alpha) rejected: it silently reintroduces
  transparency semantics and would change existing `drawMesh` alpha behavior;
  alpha masks, not maps, own cutout.
- **D2 — The alpha mask is a binary cutout at a fixed `0.5` threshold.**
  `alphaMask` samples `texture(alphaMask, uv).a`; the fragment is discarded
  when the sample is `< 0.5` and written otherwise, before lighting. The RGB
  is ignored. Rejected: multiplicative alpha (needs blending, changes the
  alpha contract, is not a "mask") and a configurable `{ texture, threshold }`
  shape (a bigger surface than `vision.md` names, and a fixed threshold keeps
  goldens and the CPU reference deterministic). Tests use opaque/transparent
  texels (alpha 0 / 255) rather than the exact boundary so 8-bit rounding
  cannot flip a result.
- **D3 — One shader, five samplers, white fallback; no permutations.**
  `shaders/mesh.glsl` declares four channel `texture2D` + `sampler` bindings
  and one alpha-mask binding; an absent color map binds the engine
  `whiteTexture` so the sample is `(1,1,1,1)` and the multiply is a no-op —
  the color path has no branches. The alpha mask uses the same fallback: an
  absent mask binds the white texture (alpha `1`), so a single unconditional
  `if (sample.a < 0.5) discard;` never fires on an unmasked material and no
  extra uniform/flag is needed. (The initial design sketched a uniform
  `alpha_mask_enabled` flag gating the discard; the white-texture fallback is
  simpler and removes the flag entirely, with identical observable
  behavior.) This upholds ADR 0026's single uniform-driven shader and settles
  the permutation question the roadmap left open. Alternatives rejected:
  build-time per-feature permutations (the machinery the roadmap explicitly
  deferred; there is no capability a permutation would expose) and a
  two-shader unmapped/all-maps split (duplicates the pipeline and fragment
  logic; F4a rejected the same shape). Sokol wires the five map textures with
  its `texture_sampler_pairs` (shared `P.smp` sampler, distinct view slots);
  the bind count stays far under the backend minimums (GLES2 guarantees 8
  fragment units).
- **D4 — UV plumbing and defaults.** The vertex stage emits the interpolated
  `uv`; the fragment stage samples every map at it. A surface without `uvs`
  already uploads the `(0,0)` default (F3), so maps stay defined for every
  F3-legal mesh. No wrap/filter/offset configuration is added: maps use the
  existing shared sampler and the surface's stored coordinates. This is why
  no `uv`-transform API enters F4b.
- **D5 — Material storage extends the existing snapshot.** `efx_material`
  gains a handle + presence flag per channel map and for the alpha mask
  (`uint64_t` handles, `uint8_t` flags), keeping the color fields and
  `shininess` value-snapshotted. `read_material` (desktop) and
  `__efxMaterial` (web) validate and copy the handles at bind time, so later
  mutation of the script object cannot change the binding — the same snapshot
  rule as F4a, with maps held by **handle** per ADR 0019.
- **D6 — Bound maps are retained by reference count, not by weak handle.**
  Each `tex_slot` gains a bind-reference count. Storing an `efx_material`
  with maps in a material slot (a `MeshData` surface or a `Mesh` surface)
  increments each referenced texture's count; replacing or clearing the
  binding, and destroying the owning `MeshData`/`Mesh`, decrements it.
  `Texture.destroy()` marks the script handle dead (`alive = 0`, so later
  script use throws) but, if the count is non-zero, sets a release-pending
  bit instead of scheduling the native release; when the count reaches zero
  the pending native release is scheduled for frame end. Playback resolves
  the native through a retained accessor, so a map whose script handle was
  destroyed keeps rendering until it is unbound — exactly the contract the
  spec pins. Alternatives rejected: a weak handle that degrades to "no map"
  when destroyed (surprising, lets a live draw silently change) — the user
  chose retention; and release-time scanning of all bindings (the registry of
  CPU-side `MeshData` objects is not globally tracked in `render.c`, so a scan
  cannot see them and would let a `MeshData`-held map die before `createMesh`).
- **D7 — Validation splits as in F4a (D10).** Type-level failures — `map`/
  `alphaMask` is not a `Texture`, is a destroyed texture, a channel color is
  malformed, `shininess` is not a number, or an unknown field is present —
  are raised in the bindings; range-level failures (`shininess <= 0` or
  non-finite) are enforced in the shared core. "Live `Texture`" means the
  script-facing handle is alive (a texture destroyed while retained still
  fails a fresh bind with `TypeError`, since its handle is dead), so desktop
  and web cannot drift.
- **D8 — CPU reference takes map samples, not textures.** `efx_lighting_shade`
  gains a `const efx_map_samples *` argument (four RGB samples + a mask
  alpha + presence) and returns whether the fragment is discarded; passing
  `NULL` reproduces the F4a neutral behavior. This keeps the reference pure C
  with no texture/GPU dependency while letting unit tests assert each
  channel's modulation and the exact `0.5` boundary analytically. The
  existing F4a tests pass `NULL` unchanged.
- **D9 — Goldens are additive; existing goldens are frozen.** New scenes at
  640×480: a diffuse map, an ambient map, a specular map, an emissive map, an
  alpha-mask cutout, a multi-map surface, and one scene whose pixels are
  compared against the CPU reference (the "absent map is neutral" check can
  also render the same scene with and without explicit white maps). Because
  absent maps contribute neutral `1`, the F2, F3, and F4a goldens MUST stay
  byte-identical — a task-level check, not a re-baseline. New scenes require
  the manual server-side llvmpipe capture before remote verification
  (`docs/verification-server.md`).
- **D10 — Desktop and web get the same wire semantics.** The web material
  wire layout is extended beyond the 17 floats to carry the five map handles
  as **doubles** (a float would truncate the 64-bit handle) plus presence
  flags; `entry.js` parses `map`/`alphaMask` as live `EfxTexture` objects and
  raises the same `TypeError`s. `createMeshData`'s `materials` array and
  `setMeshSurfaceMaterial` share one parser per side, as in F4a.

## Risks / Trade-offs

- [Cross-backend sampling/filtering precision drifts and breaks goldens] →
  maps in golden scenes use flat/checker texels with hard edges, the shared
  linear sampler, and the ±2/255 tolerance; the mask threshold is exercised
  with 0/255 texels, never the exact boundary. Verify the generated header
  compiles on the GL/D3D11/Metal/GLES3 paths before wiring playback.
- [Always sampling five textures costs fragment bandwidth / exceeds units on
  a weak backend] → one shared sampler and view slots only; the count is well
  under the GLES2 minimum of 8 fragment units; assert shader compilation on
  every backend in the standard build.
- [Reference-count drift leaks native texture memory or frees too early] →
  retain/release helpers are the only path that mutates the count; a C unit
  test drives bind → destroy → rebind → mesh-destroy and asserts the count
  returns to zero and the pending release fires; runtime-shutdown teardown
  releases anything outstanding.
- [Map retention keeps a texture alive past script intent] → this is the
  chosen contract; `Texture.destroy()` still makes the script handle
  unusable (subsequent script use throws), and the memory is bounded by the
  bindings the script actually holds.
- [The extended shader perturbs F4a output] → neutral maps by construction
  (`whiteTexture` sample is `(1,1,1,1)`, flag off); a task asserts the F2, F3,
  and F4a goldens are byte-identical on the host.
- [Web handle precision] → map handles cross the bridge as doubles, never
  packed into the float material block.
- [Mask discard interacts with depth/blending ordering] → discard runs first
  in the fragment shader, so discarded fragments write neither color nor
  depth; blend-mode behavior for surviving fragments is unchanged.

## Migration Plan

No data migration: no shipped script binds maps (the API was provisional in
`docs/js-api.md`), so F4b is purely additive. `docs/js-api.md` moves the F4b
entries from provisional to current in this change. Rollback is a revert of
the change branch; goldens are additive only and nothing is re-baselined. F2
behavior and goldens are untouched throughout.

## Open Questions

None. `uv` transforms, wrap/filter controls, and soft alpha are explicitly
future scope (Non-Goals) and none changes this design; the additive seam F4b
extends is the per-surface material snapshot, as F4a intended.
