# Design

## Context

See proposal.md — Why. The engine conveniences already exist (ADR 0060:
`efx.math.mat4.transform`, `efx.graphics.screenRay`, `efx.physics.debugDraw`,
`efx.math.clamp`/`lerp`, `efx.time.now`) and `efx.noise` exists (ADR 0059);
this change is sample content plus one sample-asset convention, so it settles
no engine decision. Constraints that shape it: curated sample directories are
self-contained resource roots (the sample asset-pack contract), samples use
only the public `efx` API and standard ES6, generated assets follow the
committed-stdlib-generator pattern (`gallery/scripts/gen-audio-assets.py`),
and the gallery smoke run is the verification harness for sample behavior.

## Goals / Non-Goals

**Goals:**

- Every demo uses the new conveniences where they replace hand-rolled code
  (transform, screenRay, debugDraw, lerp, time.now), and the demos visibly
  exercise them.
- No curated sample builds a radial falloff in script; the noise/gradient
  generators the engine now provides are used where a sample still needs
  procedural pixels.

**Non-Goals:**

- No engine/API change, no `gradientImageData`, no new sample or gameplay.
- No change to the sample asset-pack contract or the catalog.
- No golden re-baseline (samples are not goldens).

## Decisions

### D1 — One canonical radial PNG, tinted at draw time

A single 64×64 `radial.png` — white RGB, alpha `(1 − d)² · 255` over a disc
of radius `size/2`, `d` clamped to 1 — is generated by a new
`gallery/scripts/gen-radial-assets.py` (stdlib `struct` + `zlib`, no Pillow,
mirroring `gen-audio-assets.py`), written into each consuming sample
directory, and loaded with `loadImage` + `createTexture`. Every sample tints
it with the draw color, so one asset serves glows (additive) and shadows
(dark, alpha).

- *Why one asset*: every sampled falloff loop already produces white pixels
  with the same `(1 − d)²` alpha; the only variant is blob-shadow's wider,
  softer falloff (`d · 2`, alpha `· 200`). A shared image replaces all of
  them; the blob shadow keeps its flat `facing: 'plane'` decal and just
  changes falloff shape slightly — an accepted visual change for a showcase.
- *Why a copy per sample, not one shared file*: a curated sample directory is
  itself the player's resource root; a shared directory or symlink would
  break the "directory is the resource root" contract and the derived packs.
  The copies are byte-identical and small.

### D2 — Generated-asset provenance follows the audio pattern

`gen-radial-assets.py` regenerates the shipped files and supports `--check`
for drift, exactly like `gen-audio-assets.py`. `CREDITS.md` gains one row per
(sample directory, `radial.png`) naming the generator and CC0, so provenance
is reproducible from the repository. The audio generator's `--check` is not
wired into CI today; the radial check follows that precedent (documented and
runnable) rather than expanding the gate.

### D3 — `mat4.transform` replaces the local matrix ladders

`game-bot-arena`, `game-mini-golf`, and `physics-showcase` drop their
`trs(pos, scale)` helpers for `efx.math.mat4.transform(pos, 0, 0, 0, scale)`,
and `game-sky-steps`'s inline `translate ∘ scale` becomes the same call.
`transform`'s fixed `T·Ry·Rx·Rz·S` order matches the ladders being replaced
(no rotation in these call sites), so output is unchanged.

### D4 — `screenRay` replaces hand-rolled picking

`game-bot-arena` and `game-mini-golf` currently build the camera basis and an
NDC ray by hand, then intersect the ground plane (golf additionally calls
`physics.raycast`). They drop the basis/NDC math for
`efx.graphics.screenRay(mouse.x, mouse.y)` and keep only the plane
intersection; golf feeds the returned ray into its existing
`physics.raycast`. The cursor is already reported in frame pixels (ADR 0060),
so `screenRay(...efx.mouse.position)` is the canonical call and the picking
math shrinks to the intersection.

### D5 — `debugDraw` as an opt-in view in the physics showcase

`physics-showcase` keeps its scene — those draws are the showcase's visual,
not redundant collider plumbing — and gains a key toggle (`d`, off by
default) that calls `efx.physics.debugDraw()` from its render hook. Debug off
keeps the normal look; debug on overlays every collider, including the sensor
volume, as engine-drawn hulls.

### D6 — `efx.time.now` for animation time; keep dt for simulation

Samples that accumulate `t += dt` / `clock += dt` for animation switch to
`efx.time.now` (frame-start snapshot, stall-clamped). The per-frame `dt` used
for `physics.step` and velocity integration stays the frame's `dt`; where a
sample also clamps `dt` before stepping, the clamp stays (simulation
stability), so only the animation clock changes source. This preserves
behavior on normal frames and bounds animation time on a stall.

### D7 — `math.lerp` only where a real blend exists

`math.lerp` replaces hand-written linear blends (for example the audio
showcase's volume fade). No sample is contorted to use it; if a sample has no
linear blend, it simply does not adopt `lerp`.

### D8 — Mini Golf grass uses `efx.noise`

`game-mini-golf`'s LCG `noiseTexture` becomes
`efx.noise.imageData(64, 64, { seed, frequency })` → `createTexture(...,
{ wrap: 'repeat' })`. Noise values (approximately `[-1, 1]`) are remapped to
the grass brightness the sample already uses, keeping the procedural, no
third-party-asset contract; the sample still generates its course geometry.

### D9 — Spec scope: only contradicted requirements change

Only `web-gallery` requirements whose text the change makes inaccurate are
modified: the particle-showcase and skybox/blob-shadow "prefer procedural"
clauses (the shipped asset is now the norm), Mini Golf's "only shipped asset
is the font" (it now also ships the radial image) and Bot Arena's
"procedurally generated textures" (glow decals now use the shipped image).
The requirements that merely enumerate shipped assets without exclusivity
(`game-bloom-breakout`, `game-glow-gauntlet`, `game-sky-steps`) stay as they
are — adding a radial image does not falsify their scenarios — and a new
`Shared radial glow texture asset` requirement pins the convention. This
keeps the delta small and the specs true.

## Risks / Trade-offs

- [Blob-shadow falloff changes shape when it adopts the shared image] →
  Accepted: it remains a flat `facing: 'plane'` decal and the showcase's point
  is the decal behavior, not the exact falloff curve; the change is recorded
  in the spec.
- [`efx.time.now` changes stall behavior for samples that never clamped dt] →
  Intended and bounded (the clock clamps long stalls); simulation dt is
  unchanged, so gameplay is unaffected.
- [Eight byte-identical PNG copies look like duplication] → They keep each
  sample a self-contained resource root; the generator + `--check` make them
  a single source of truth.
- [Samples are only covered by the gallery smoke, not goldens] → The smoke
  drives every sample in pinned headless Chrome and fails on any console/page
  error; the server `verify_remote.py gallery` suite runs it before the gate.

## Migration Plan

Sample source and assets change together per sample (no intermediate state
where a sample loads a file it does not ship). Rollback is a revert; no data
or format dependency. The `package curated samples` job re-derives packs from
the updated directories automatically.

## Open Questions

- None. The radial falloff formula, the generator's location, and the
  affected requirement set are pinned above.
