# Proposal

**Roadmap position:** Cross-cutting showcase/tooling infrastructure — no
feature milestone. It adds curated gallery content that presents the
already-shipped F14 audio API; it does not start or reopen a ladder
milestone. Precedent: the archived `gallery-input-showcase` and
`gallery-asset-showcase` changes.

## Why

F14 shipped engine-owned audio playback (`efx.audio`: streamed background
music, a 32-voice effect bank, WAV/MP3 loading, no-device soft-fail and web
autoplay unlock), but the only place it is exercised is headless tests. The
gallery's other features each have a visitor-facing showcase, while audio —
which a visitor can actually *hear* — has none. A visitor cannot see the
author-facing surface (`playBackgroundMusic` / `playAudioEffect`), the
engine-owned mixing model, or the browser autoplay-unlock behavior without
reading the spec.

## What Changes

- **A curated audio showcase sample.** `gallery/samples/curated/
  audio-showcase.js`: an interactive sound-board that uses the whole F14
  surface —
  - `efx.audio.playBackgroundMusic(path, { loop, volume })` for a looping
    streamed track, with `pause`/`resume`/`setVolume` controls and a live
    `playing` readout;
  - `efx.audio.playAudioEffect(path, { volume, pan, pitch })` (the prelude
    sugar) fired from clickable pads and number keys, with pan from the
    click x and pitch from the click y, so overlapping voices are audible;
  - `efx.audio.resume()` plus a first-interaction unlock, demonstrating the
    web autoplay rule (the same script runs on desktop, where the device is
    available immediately).
  - a small animated mixer panel (procedural quads + a baked font) that
    pulses on each effect and shows the music/volume state.
- **An authored asset pack.** `gallery/samples/curated/audio-showcase.zip`
  (a committed, deterministic pack beside the manifest) holding the looping
  `music.mp3`, three short effect WAVs (`blip.wav`, `chime.wav`,
  `thud.wav`), and a CC0 font. The WAVs are synthesized deterministically by
  the pack script; the MP3 and font are committed sources. The pack is
  regenerated by `gallery/scripts/pack-curated-audio.py` (with `--check`
  for drift).
- **Manifest + catalog + credits.** A `manifest.json` entry (category
  `Showcase`), the regenerated `gallery/src/samples/generated.json`, and a
  `CREDITS.md` row/recipe for the pack (font provenance; WAV/MP3 authored
  in-repo).
- **A player smoke test.** `smoke_showcase_audio` runs the sample headless
  against its pack on the desktop player, so a broken pack or script fails
  the suite. The gallery smoke also drives it (its id sorts into the first
  samples the smoke runs).

## Impact

- **Content:** `gallery/samples/curated/audio-showcase.js` (new),
  `gallery/samples/curated/audio-showcase.zip` (new pack),
  `gallery/samples/curated/audio/` (committed pack sources: `music.mp3`,
  `font.ttf`), `gallery/scripts/pack-curated-audio.py` (new),
  `gallery/samples/curated/manifest.json` (one entry),
  `gallery/samples/curated/CREDITS.md` (one row + recipe).
- **Tests:** `tests/CMakeLists.txt` gains `smoke_showcase_audio` (native
  player, `--script` against the pack).
- **Docs:** `AGENTS.md` gallery bullet notes the audio demo. No
  `docs/js-api.md` and no `gallery/src/api/efx.d.ts` change — the script API
  is unchanged (F14 already documented and typed).
- **Verification:** native `smoke_showcase_audio` + the gallery smoke on the
  server; the four-target gate already exercises the engine. No golden
  baselines change and no engine code changes.

## Non-goals

- No engine, renderer, or script-API change; no new `efx` function.
- No golden scene (F14 has no visual gate).
- No third-party audio assets — the pack is authored in-repo (CC0 font
  reused from the text showcase).
- No gallery-shell change (the runner, catalog generation, and smoke are
  reused as-is).
