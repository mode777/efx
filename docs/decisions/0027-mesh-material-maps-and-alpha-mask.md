# 0027 — Mesh material maps are five always-bound samplers (white fallback); maps are retained while bound

Status: Accepted (2026-09, change `f4b-maps-alpha-masks`)

Supports: vision.md — "Simple phong material system: Ambient, Diffuse,
Specular, Emissive with support for maps for each of those channels";
"Support for alpha masks"; roadmap F4b (per-channel maps + alpha masks);
ADR 0026 (single uniform-driven mesh shader, no F4a permutations — this
change is where a permutation could have arrived); ADR 0011/0012 (resource
classification and memory discipline); ADR 0019 (value snapshot vs handle
reference); ADR 0024 (materials bind per surface, never globally).

## Context

F4a settled the mesh shader as one uniform-driven program with no per-material
permutations and explicitly left the map/shader question to F4b. F4b adds four
per-channel maps and a material-level alpha mask, consuming the `uvs` stored
since F3. The material object is JS-managed and snapshotted per surface (colors
by value, per ADR 0019), while a `Texture` is a native-backed, GC-finalized
class with a deterministic `destroy()`. A material binding persists on the
`Mesh` across frames — unlike a frame-transient display-list record — so a
destroyed map could otherwise dangle. The full process record is
`openspec/changes/f4b-maps-alpha-masks/`.

## Decision

- **One shader, five texture bindings, white fallback.** `shaders/mesh.glsl`
  declares four channel map `texture2D`+`sampler` bindings (bind slots 0..3)
  and one alpha-mask binding (slot 4), generated by the pinned sokol-shdc
  (ADR 0021). Every mesh draw binds all five; an absent color map binds the
  engine `whiteTexture`, so its sample is `(1,1,1,1)` and the channel
  multiply is neutral; an absent alpha mask binds the same texture, whose
  alpha `1` never satisfies the unconditional `if (sample.a < 0.5) discard;`.
  There are **no** per-material shader permutations and no uniform feature
  flags. The per-channel factor is `M_c = map ? texture(map, uv).rgb :
  (1,1,1)`; `uv` is the surface's interpolated coordinate (missing `uvs`
  default to `(0,0)`); material channel alphas and map alphas are ignored by
  shading and the output alpha stays the albedo alpha.
- **The alpha mask is a binary cutout at a fixed `0.5`.** A present mask's
  alpha below `0.5` discards the fragment before lighting; `0.5` and above
  survive. This is the only alpha the maps expose.
- **A bound map retains its `Texture`.** Each texture slot carries a
  bind-reference count; storing a material that references a map (on a
  `MeshData` surface or a `Mesh` surface) increments it, and replacing or
  clearing the binding — or destroying the owning `MeshData`/`Mesh` —
  decrements it. `Texture.destroy()` makes the script handle dead
  immediately, but its native storage is released only when the count
  reaches zero (a release-pending bit holds it until then). Playback
  resolves retained handles through the texture registry, so a map whose
  script handle was destroyed keeps shading until it is unbound. A fresh
  bind of a dead texture still throws `TypeError`.
- **The map handles cross the web bridge as doubles**, not packed into the
  17-float material block, so the 64-bit texture handle survives.

## Consequences

- F5/F6 must respect the same single mesh shader: map-like features are
  additive uniforms/bindings inside this source, never a second
  consumer-visible shader surface (ADR 0015). F6 binds imported glTF
  textures into these five slots and inherits the retention rule.
- Unmapped materials are byte-for-byte the F4a result (neutral white
  fallback), so the committed F2/F3/F4a goldens stay valid; F4b goldens are
  additive.
- `uvs` are now consumed by shading; they remain validated and stored on
  every F3-legal mesh, and a surface without them samples `(0,0)`.
- Bound maps can outlive a script's `destroy()` until unbound — intended,
  and bounded by the bindings the script holds. The retention count is the
  only path that mutates texture lifetime, so a count that leaks is a
  native leak; teardown releases anything outstanding.
- The reference-count field and release-pending bit live in the render
  texture registry (`src/render/render.c`); materials hold `uint64_t` map
  handles and no native pointers, keeping materials JS-managed (ADR 0011).

## Rejected alternatives

- **Build-time shader permutations per map-feature set**: rejected — the
  roadmap deferred this machinery to F4b only if maps needed a capability a
  uniform could not express; the white fallback and a sampled discard express
  every case, so a permutation would add pipeline-selection complexity for
  nothing.
- **A separate unmapped/all-maps shader**: rejected — duplicates the
  fragment logic and pipeline surface; F4a rejected the same shape, and the
  neutral fallback already gives unmapped surfaces identical output.
- **A uniform `alpha_mask_enabled` flag gating the discard**: rejected after
  implementation — binding the white texture for an absent mask makes the
  unconditional discard a no-op, removing a uniform without changing
  behavior.
- **Weak map handles (treat a destroyed texture as "no map")**: rejected —
  a live draw would silently change appearance when the script destroys a
  texture; retention is the predictable contract and mirrors the
  display-list keep-alive rule (ADR 0019).
- **Release-time scanning of all material bindings**: rejected — CPU-side
  `MeshData` objects are not globally tracked by the render core, so a scan
  cannot see them and a `MeshData`-held map could die before `createMesh`.
- **`{ texture, threshold }` or multiplicative alpha masks**: rejected — a
  fixed binary cutout is what vision.md names, keeps goldens and the CPU
  reference deterministic, and avoids introducing blending semantics into
  the mask.
